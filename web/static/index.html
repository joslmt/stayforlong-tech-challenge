Decisions, without the jargon

Frequently asked questions

The important business and technical choices behind this implementation.

How is profit calculated?

Profit is the whole-stay selling rate multiplied by its margin percentage. The API receives whole euros, calculates exactly internally, and rounds half-up to two decimal places only when writing the response.

What does the data endpoint measure?

It uses every booking in the request. The average is total profit divided by total nights; minimum and maximum compare each booking's profit per night.

How does the revenue endpoint select bookings?

It maximises occupied nights. If two schedules occupy the same number of nights, it chooses the most profitable one, then the schedule containing the earliest submitted request.

How is the cleaning window handled?

Check-out is 11:00, cleaning runs from 11:00 to 12:00, and check-in is 15:00. A new stay may therefore begin on the previous stay's checkout date.

Why are request IDs returned chronologically?

A schedule is easier to operate when it reads from earliest to latest. This is an explicit decision and differs from the apparent input ordering in one supplied example.

Why is there no database?

Both endpoints calculate a result solely from the current request. Persisting that temporary input would add failure modes without serving a business requirement.

What input is accepted?

Between 1 and 10,000 bookings, unique UUID v4 request IDs, valid calendar dates, 1–365 nights, positive whole-euro rates, and margins from 0% to 100%. Unknown JSON fields are rejected.

Why must request IDs be UUID v4?

A fixed identifier format gives every partner the same validation rule and avoids accepting ambiguous free-form IDs. UUIDs are compared case-insensitively and returned in canonical lowercase form.

Can a zero-margin booking be selected?

Yes. The primary goal is occupied nights, so a zero-profit stay is valid when it improves occupancy.

Why can the live OAS look different?

The published specifications disagree about integer versus decimal metrics and the scope of revenue statistics. This project follows the decimal, selected-schedule contract supplied with the challenge and documents every difference in the repository.
